# Описание выхода

Результат расчёта — один GeoJSON `FeatureCollection` в EPSG:4326 (ТП 7): все варианты в одном массиве `features`,
различаются полем `variant_id`. У каждого типа объекта — только свои атрибуты, полей других типов со значением
`null` нет. Точки подключения повторно не выводятся. Выгрузка — `GET /api/runs/{id}/result.geojson`
или шаг «Выгрузка» в интерфейсе; пишется потоково, размер не ограничен памятью (до 500 МБ по ТЗ).

## Объекты

| `object_type` | Геометрия | Атрибуты |
|---|---|---|
| `heat_network` — новый участок | LineString | `start_node_id`, `end_node_id`, `flow_tph`, `diameter`, `length`, `laying_method` (`base` / `special`), `depth_start`, `depth_end` (в 2D — `null`), `cost` |
| `heat_chamber` — новая камера | Point | `diameter`, `cost` |
| `technical_node` — технический узел | Point | — |
| `variant_summary` — сводка варианта | `null` | `rank`, `construction_cost`, `chamber_construction_cost`, `existing_chamber_tie_in_count`, `existing_chamber_tie_in_cost`, `unconnected_penalty`, `calculated_cost`, `new_network_length`, `score`, `unconnected_oks_ids` |

Во всех объектах есть `id`, `object_type`, `variant_id`. Отдельного объекта места присоединения (`tie_in`) нет:
присоединение — это либо новая камера прямо в точке существующего участка, либо конец нового участка в существующей
камере. Объектов реконструкции тоже нет: действующая редакция техприложения существующую сеть не реконструирует.

## Как устроены связи

- **Идентификаторы** наших объектов — `v<вариант>-<тип>-<номер>`: `v1-seg-12`, `v1-ch-5`, `v1-node-2`,
  `v1-summary`. Уникальны в пределах файла. Идентификаторы входных объектов (`start_node_id`, `end_node_id`,
  `unconnected_oks_ids`) выводятся с тем же типом, что во входе: целое число — числом, остальное — строкой.
- **Топология новой сети.** `start_node_id` — узел со стороны места присоединения, `end_node_id` — со стороны
  точки подключения. Узел — существующая камера (её `id` из входа), новая камера (`heat_chamber.id`), технический
  узел или точка подключения (`id` объекта `oks_connection_point` входа). От места присоединения до каждой точки
  его части сети — ровно один путь. Поворот без смены параметров остаётся внутренней вершиной `LineString`.
- **Присоединение к участку** — новая камера в выбранной точке существующего участка; геометрия существующей сети
  не меняется, сам участок в выходе не переписывается. ДУ такой камеры — наибольший из примыкающих к ней: новых
  участков и обеих половин существующей линии.
- **Присоединение к существующей камере** — если до неё не больше 10 м и после подключения в ней будет не больше
  четырёх примыкающих участков. Каждый новый участок, заканчивающийся в ней, — одна врезка за 5 млн руб.
- **Технический узел** ставится там, где меняется способ прокладки (обычная / спецпроход) или коэффициент
  стоимости без разветвления; участок делится, у каждой части свой `laying_method` и стоимость.

## Стоимости и оценка

- `heat_network.cost` = длина × цена метра ДУ × коэффициент спецпрохода (1 — обычная прокладка, 1,6 — дорога,
  1,75 — трамвай, 1,25 — газ, 1,15 — кабель, 1,05 — существующая теплосеть; при наложении — наибольший).
  Отдельной надбавки за поворот нет.
- `heat_chamber.cost` — по наибольшему ДУ примыкающих участков (3 / 5 / 8 / 12 млн руб.); она уже включает
  присоединение к существующей сети.
- `variant_summary`: `construction_cost` = участки + новые камеры + врезки в существующие камеры;
  `calculated_cost` = `construction_cost` + `unconnected_penalty`;
  `score` = 0,7 · `calculated_cost` / 25 млн + 0,3 · `new_network_length` / 100; `rank` 1 — наименьший `score`.
- Дополнительные `properties` в выходе допускаются и при проверке обязательной части игнорируются; мы их не пишем.

## Что есть в сервисе сверх файла выгрузки

Для демонстрации и разбора сервис хранит результат ещё и в PostGIS и отдаёт по вариантам
(`GET /api/runs/{id}/variants/{variant}.geojson`). Там, кроме объектов выгрузки, есть слои, которых нет в формате
ТП 7 и которые в файл выгрузки не пишутся (`derived: true`):

| Слой | Что |
|---|---|
| `attachment` | место присоединения части новой сети: существующий объект, его ДУ, расход, врезка это в камеру или новая камера на участке |
| `flow_change` | каждый участок существующей сети, по которому пойдёт дополнительный расход: было, добавлено, стало, ДУ был / нужен, хватает ли пропускной способности (справочно, в обязательный расчёт не входит) |
| `length_run` | непрерывная часть новой сети одного ДУ: суммарная длина (она и учитывается), длина по самому длинному пути, предел ДУ, доля от предела |
| `unconnected_oks` | неподключённая точка (контур или точка подключения) с причиной ([unconnected.md](unconnected.md)) |

В сводке расчёта (`GET /api/runs/{id}`) к каждому варианту есть пояснения: способ подключения, объяснение,
число частей сети, присоединений, камер и разветвлений, поворотов на км, отношение длины трассы к прямой.
