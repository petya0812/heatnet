# Данные для разработки и проверки

## Наборы

Все наборы лежат в `test-data/`; таблица «файл → что это, объектов, ОКС, что проверяет, ожидаемый итог» —
[test-data/README.md](../test-data/README.md). Коротко: `contest-lct.geojson` — **конкурсный набор**
(район ЗИЛ, 144 объекта, 17 ОКС; в интерфейсе — группа «Проекты», набор «ЗИЛ»), `contest-osm*.geojson` — тот же
район с реальным окружением OSM и дополнительными ОКС, остальное — синтетика из `tools/gen_testdata.py` (сценарии на одно правило, плотный и
случайный город). Итоговые прогоны по всем наборам (S, время, неподключённые) — [metrics.md](metrics.md).

## Как завести наборы в работающем сервисе

```bash
python3 tools/seed_datasets.py            # ЗИЛ и три примера (добавить недостающие)
python3 tools/seed_datasets.py --all      # все наборы
python3 tools/seed_datasets.py --reset    # удалить все наборы в сервисе и завести заново (с --all — все)
```

Имя набора в сервисе — это имя файла, под которым он загружен, без расширения; скрипт копирует файл под
человеческим названием и загружает уже так. Название — «Группа · Название» (разделитель: пробел, средняя точка
U+00B7, пробел): интерфейс делит по нему и показывает группу отдельно. Группы (префикс → группа в интерфейсе):
«Проект» → «Проекты» — рабочие данные (конкурсный набор ЗИЛ), «Пример» → «Примеры» — небольшие наборы на одно
правило или сценарий, «Нагрузка» → «Большие наборы» — большие наборы для замеров.
Список названий и порядок — `DATASETS` в шапке скрипта; ЗИЛ грузится последним, чтобы в списке (новые сверху) быть
первым.

## Конкурсный набор

Формат технического приложения (редакция 18.09.2026) совпадает с форматом конкурсного набора: у сети только
`diameter`, у камер нет диаметра, цель подключения — точка с расходом, здания приходят ограничениями типа `oks`. В наборе три типа ограничений: `oks`, `water`, `railway`.
Наборы `contest-osm*` сделаны в **той же структуре**, но с типами ограничений из таблицы 2 технического приложения — чтобы
проверять и спецпроходы (дороги, трамвай), и плотную реальную застройку.

**Редакция организаторов от 18.09.** Состав объектов тот же, изменения точечные:
`diameter` участков 121–127 — 300 → 400, 142 — 500 → 400, 143 — 500 → 300; источник сдвинут в узел участка 116;
имя источника без кавычек. Все замеры на конкурсном наборе сделаны на этой редакции.

## Наборы с OSM

Наборы `contest-osm*.geojson` собраны из данных OpenStreetMap (© участники OpenStreetMap, ODbL): здания, дороги,
трамвай, вода и зелёные зоны района переведены в типы ограничений техприложения, объекты и сеть конкурсного набора —
без изменений. Дополнительные ОКС в `contest-osm-50` и `contest-osm-big` поставлены в реальные здания рядом с сетью.

## Источники и ограничения по данным

- **Конкурсный набор** — используется как получен (редакция организаторов от 18.09); это единственные реальные данные о сети.
  Постановка, техническое приложение и разъяснения к нему в репозиторий не входят: на них ссылаются по названию.
- **OpenStreetMap** © участники OpenStreetMap, лицензия ODbL. Наборы `contest-osm*.geojson` — производная работа
  под ODbL, при передаче наборов ссылка на источник обязательна.
- **Синтетические наборы** — целиком из `tools/gen_testdata.py`, ограничений нет; координаты — вымышленный район
  в UTM 37N рядом с Москвой, к реальной местности не привязаны.
- **Большие файлы** (3 ГБ для проверки потокового импорта) в репозиторий не кладутся: собираются на месте в
  папке `generated/` внутри `test-data/` (она в `.gitignore`).
