# API

Описание всех методов с примерами ответов — Swagger UI: `http://сервер:8080/swagger-ui.html`,
машиночитаемая спецификация — `http://сервер:8080/v3/api-docs`. Swagger сгруппирован по сценарию, восемь
разделов: 1. Наборы данных → 2. Расчёт → 3. Результат и выгрузка → 4. Разбор результата → 5. Версии набора и
правки → 6. Карта → 7. Справочники → 8. Служебное; внутри раздела операции идут в порядке сценария, сценарий из
пяти запросов — в шапке. У моделей ответов (`Dataset`, `Run`, `VariantSummary`, `Validation`, `Issue`, …) есть
описания полей; примеры — ответы реального расчёта, собираются с работающего сервиса `python3 tools/api_examples.py`
в `src/main/resources/openapi/examples.json`.

Все ответы — JSON, кроме выгрузки (GeoJSON), тайлов (Mapbox Vector Tile) и отчёта (HTML). Координаты —
EPSG:4326, время — UTC, идентификаторы наборов и расчётов — UUID.

## Порядок работы

```bash
B=http://localhost:8080
# 1. загрузить набор (до 3 ГБ, файл пишется на диск и импортируется потоково в фоне)
DS=$(curl -s -F "file=@test-data/contest-lct.geojson" $B/api/datasets | jq -r .id)
# 2. дождаться импорта: status UPLOADED → IMPORTING → READY (или FAILED), в progress — прочитано байт
curl -s $B/api/datasets/$DS | jq '{status, progress, feature_count, issue_counts}'
# 3. замечания к входным данным
curl -s "$B/api/datasets/$DS/issues?severity=ERROR"
# 4. запустить расчёт по всем перспективным ОКС; тело необязательно
RUN=$(curl -s -X POST -H 'Content-Type: application/json' -d '{"existing_flow":"ZERO"}' \
  $B/api/datasets/$DS/runs | jq -r .id)
# 5. дождаться расчёта: QUEUED → RUNNING (progress: этап, сколько подключений перебрано) → DONE
curl -s $B/api/runs/$RUN | jq '{status, progress, validation: .validation.errors}'
# 6. выгрузить результат
curl -s -o result.geojson $B/api/runs/$RUN/result.geojson
```

## Наборы

| Метод и путь | Что |
|---|---|
| `POST /api/datasets` (multipart, поле `file`) | загрузить GeoJSON; ответ 202 `{id, status}`. 507 — не хватает места на диске |
| `GET /api/datasets` | список наборов |
| `GET /api/datasets/{id}` | статус, ход импорта (`progress.bytes_read / bytes_total`), число объектов по типам, сводка замечаний, охват |
| `GET /api/datasets/{id}/issues?severity=&limit=` | замечания к входу: `severity` (ERROR, WARNING, INFO), `code`, `feature_id`, `message` |
| `POST /api/datasets/{id}/cancel` | отменить импорт (в очереди или идущий) |
| `DELETE /api/datasets/{id}` | удалить набор со всеми расчётами, таблицами и файлами; идущие импорт и расчёты отменяются |
| `GET /api/datasets/{id}/bbox` | охват `[minLon, minLat, maxLon, maxLat]` |
| `GET /api/datasets/{id}/tiles/{z}/{x}/{y}.mvt` | векторный тайл входных слоёв для карты |
| `GET /api/datasets/{id}/features/{fid}` | объект набора по `id` (GeoJSON) — переход к объекту из диагностики |

Слои тайла: `network` (ДУ, расход, `upstream_object_id`), `oks`, `source` — с z9; `chambers`, `connection_points`,
`restrictions` (`restriction_type`) — с z13; `buildings` — с z14. Тайлы режутся из PostGIS по пространственному
индексу (`ST_AsMVT`), карта никогда не загружает набор целиком; на наборе 3 ГБ (10 млн зданий) тайл — 5–20 мс.

## Проверка набора и версии

| Метод и путь | Что |
|---|---|
| `GET /api/datasets/{id}/overview` | проверка набора для интерфейса: версии (`lineage`), что пришло (типы, сеть по ДУ, ОКС и расходы, ограничения с правилом), замечания по кодам с пояснением простым языком и группой (`assumption` — достроено сервисом, `problem`, `note`), готовность к расчёту (`readiness`, блокирующие проверки) |
| `GET /api/datasets/{id}/issue-features?code=` | объекты, к которым относится замечание одного кода (GeoJSON) |
| `POST /api/datasets/{id}/versions` | новая версия набора с правками входа; ответ 202 `{id, status: IMPORTING}`. Исходный набор не меняется |
| `PUT /api/datasets/{id}/edits` | заменить правки версии; 409 — у версии уже есть расчёты или это загруженный файл |

Тело новой версии: `{"note": "что за правка", "edits": [...]}`, до 500 правок. Операции (`op`), у каждой
необязательный `comment` до 500 символов:

| `op` | Поля | Что делает и что проверяется |
|---|---|---|
| `add_restriction` | `restriction_type`, `geometry` | добавляет ограничение: тип из таблицы 2 ТП, полигон в EPSG:4326 площадью от 1 м² до 25 км² |
| `remove_object` | `target_id` | исключает объект родительского набора из версии. Объект должен быть в родительской версии; источник исключить нельзя; последнюю точку подключения ОКС исключить нельзя |
| `set_attribute` | `target_id`, `attribute`, `value` | меняет один атрибут объекта; атрибут должен подходить типу объекта |

Атрибуты `set_attribute`: `diameter` — ДУ в мм из номенклатуры справочника (`heat_network`, `heat_chamber`);
`flow_tph` — расход 0…10000 т/ч (`oks_connection_point`, `heat_network`); `upstream_object_id` — id существующего
объекта сети (`heat_network`, `heat_chamber`, `source`) или `null` (`heat_network`); `restriction_type` — тип из
таблицы 2 ТП (`restriction`). Остальные атрибуты отклоняются.

Примеры: `{"op": "add_restriction", "restriction_type": "prohibited_site", "comment": "стройплощадка",
"geometry": {"type": "Polygon", "coordinates": [...]}}`, `{"op": "remove_object", "target_id": "seg-12"}`,
`{"op": "set_attribute", "target_id": "seg-12", "attribute": "diameter", "value": 200}`.

Версия — отдельная копия данных с применёнными правками; каждая правка попадает в диагностику версии кодом
`edit.restriction_added`, `edit.object_removed` или `edit.attribute_changed`. Удаление набора удаляет и его версии.
У набора в ответах: `parent_id`, `root_id`, `version`, `edits`, `note`, `run_count`.

## Параметры

| Метод и путь | Что |
|---|---|
| `GET /api/params` | каталог параметров: класс (`norm` — правило технических требований, `interpretation` — как применяется правило, которое можно прочитать по-разному, `data_assumption` — значение, которого нет во входных данных, `algorithm` — настройка трассировки), название и описание простым языком, документ-источник (`source`) и разъяснение (`basis`), значения и что меняется на практике, условие показа (`depends_on`), типы ограничений справочника с правилом. Тот же список — [parameters.md](parameters.md) |
| `GET /api/run-params` | параметры расчёта по умолчанию (настройки сервиса) |

## Расчёты

| Метод и путь | Что |
|---|---|
| `POST /api/datasets/{id}/runs` | запустить расчёт; ответ 202 `{id, status: QUEUED}`. 409 — набор не готов или в нём нет источника, сети или ОКС, 400 — неверные параметры, 503 — очередь заполнена |
| `GET /api/datasets/{id}/runs` | расчёты набора: статус, параметры, S лучшего варианта, число нарушений |
| `GET /api/runs/{id}` | статус и ход расчёта, параметры, сводка по вариантам, причины неподключения, отчёт проверки, диагностика |
| `POST /api/runs/{id}/cancel` | отменить расчёт в очереди или идущий |
| `DELETE /api/runs/{id}` | удалить расчёт с результатом |
| `GET /api/runs/{id}/validation` | отчёт проверки обязательных правил |
| `GET /api/runs/{id}/result.geojson` | выгрузка результата в формате раздела 7 технического приложения (все варианты в одном файле) |
| `GET /api/runs/{id}/variants/{variant}.geojson?derived=true` | объекты одного варианта для карты, с `derived=true` — ещё демонстрационные слои |
| `PATCH /api/runs/{id}` | `{"name", "note", "pinned"}` — название, заметка, закрепление (закреплённый не удаляется по сроку хранения) |
| `GET /api/runs/{id}/journal?variant=1&after=0` | журнал построения варианта (координаты EPSG:4326): `start` (порядок ОКС и их точки), `connect` / `rebuild` (трасса, выбранное место присоединения и рассмотренные места с оценкой S, изменения новой сети, врезки и разветвления, нагруженные участки существующей сети), `unconnected`, `finish`. Пока расчёт идёт — `live: true`, шаги одного построения с номера `after`, в `builds` — готовые построения с оценкой |
| `GET /api/runs/{id}/oks/{oks}/search` | поиск трассы одного ОКС с записью шагов, с параметрами расчёта, до существующей сети без учёта других ОКС варианта: точки поворота, порядок просмотра, отвергнутые отрезки с видом препятствия, зоны отступов и коридоры пересечений, найденная трасса или причина |
| `GET /api/runs/{id}/variants/{variant}/report.html?download=` | отчёт по варианту — HTML для печати: сводка, карта, показатели, ОКС, проверка правил, параметры с основанием, версии данных и восполненные значения |
| `GET /api/compare?a={run}:{variant}&b={run}:{variant}` | сравнение двух вариантов (одного расчёта или разных расчётов и версий набора): показатели с разницей и что лучше, отличия параметров, правки данных только в А или только в Б, общая и различающаяся длина новой сети (совпадение — 1 м), объяснение, почему один вариант выше |
| `GET /api/compare/features?a=&b=` | то же на карте: новая сеть «общая / только в А / только в Б» и врезки (GeoJSON) |
| `GET /api/status` | расчёты в работе и в очереди |

Тело запуска расчёта — все поля необязательны, незаданные берутся из настроек сервиса (`GET /api/run-params`);
пустое тело или его отсутствие — расчёт с параметрами по умолчанию. Правила технических требований переключателей
не имеют: задать можно недостающие данные и настройки трассировки, которые только ужесточают правила. Неизвестные поля игнорируются, значение
вне диапазона или не того типа — 400 `{"error": …}`.

```json
{
  "turn_penalty": 0.15,
  "existing_flow": "ZERO",
  "existing_flow_share": 0.5,
  "extra_clearance_m": 0,
  "min_crossing_angle_deg": 45,
  "turn_angles": "45_90",
  "turn_angles_strict": false,
  "joint_connection": true,
  "name": "сеть загружена на 50 %",
  "note": "смотрим запас пропускной способности"
}
```

| Поле | Диапазон, по умолчанию | Что |
|---|---|---|
| `turn_penalty` | 0…10, **0,15** | штраф за поворот в единицах оценки S — предпочтение прямых трасс при поиске; на стоимость не влияет |
| `existing_flow` | `ZERO` \| `CAPACITY_SHARE`, **`ZERO`** | расход существующей сети, если его нет во входных данных: `ZERO` — сеть свободна, `CAPACITY_SHARE` — занята долей пропускной способности ДУ (для слоя «нужен больший ДУ») |
| `existing_flow_share` | 0…1, **0,5** | доля пропускной способности ДУ при `existing_flow=CAPACITY_SHARE` |
| `extra_clearance_m` | 0…10 м, **0** | дополнительный отступ от зданий и ограничений сверх отступа по правилам; отступ по правилам — минимум, он только увеличивается |
| `min_crossing_angle_deg` | 45…90°, **45** | минимальный угол пересечения дорог и трамвайных путей; 45 — по правилам, больше — трасса пересекает ближе к перпендикуляру |
| `turn_angles` | `ANY` \| `30_60_90` \| `45_90` \| `90`, **`45_90`** | углы поворота трассы: любые до 90°; кратные 30°; 45° и 90°; только прямые. Трасса ищется по направлениям застройки вокруг ОКС с этим шагом |
| `turn_angles_strict` | **`false`** | если у ОКС нет трассы с выбранными углами: `false` — построить с любыми углами до 90°, `true` — оставить без трассы (причина `NO_ROUTE`, в `detail` — углы). При `turn_angles=ANY` не действует |
| `joint_connection` | **`true`** | совместное подключение нескольких ОКС через одну врезку; при `false` — каждый ОКС своей трассой и своей врезкой |
| `name`, `note` | строка | название (по умолчанию — из параметров, отличных от настроек сервиса) и заметка; не параметры расчёта |

Действующие значения расчёта — в `params` ответа `GET /api/runs/{id}`; описания полей — `RunParams`.

Сводка варианта содержит ещё `plain` — вариант словами — и `oks[]`: для каждой точки подключена ли, как (своё
присоединение или разветвление новой сети), куда присоединяется, ДУ, длина и стоимость своей ветки, повороты,
пересекаемые спецпроходы, путь от места присоединения (`path_segment_ids`), какие точки питаются через то же
присоединение, участки существующей сети до источника; для неподключённой — причина.

Сводка варианта в `GET /api/runs/{id}` (`summary[]`): поля `variant_summary` из ТП 7.2 (`rank`, `score`, стоимости
по статьям, `new_network_length`, `unconnected_oks_ids`) и пояснения — `strategy` (совместное / раздельное),
`explanation`, число частей сети, присоединений, камер, разветвлений, участков в спецпроходе, поворотов на км,
отношение длины трассы к прямой, время расчёта, `capacity_shortfalls` — сколько участков существующей сети не
пройдут по пропускной способности (справочно), `unconnected[]` — точки без маршрута с причиной
([unconnected.md](unconnected.md)).

## Статусы

| Объект | Статусы |
|---|---|
| Набор | `UPLOADED` (в очереди на импорт) → `IMPORTING` → `READY` / `FAILED` / `CANCELLED` |
| Расчёт | `QUEUED` → `RUNNING` → `DONE` / `FAILED` / `CANCELLED` |

## Ошибки

Ошибка API — JSON `{"error": "что произошло"}` с кодом ответа; это касается и неразобранного тела
(`{"turn_penalty": "abc"}` → 400 `{"error": "Field 'turn_penalty': Cannot deserialize value …"}`), неверного
формата UUID в пути (400 `{"error": "Invalid value of 'id': Invalid UUID string: abc"}`), неверного
`Content-Type` (415, например загрузка без `-F file=@…`) и метода (405). Исключение — путь, которого нет в API
(`/api/nothing`): его отдаёт контейнер сервлетов стандартным телом Spring с кодом 404.

| Код | Когда |
|---|---|
| 400 | некорректные параметры или тело запроса: значение вне диапазона, не тот тип, не JSON |
| 404 | набор, расчёт, объект или вариант не найден (номер варианта вне 1…3 — 400) |
| 405, 415 | метод или `Content-Type` не подходят операции |
| 409 | состояние не позволяет действие: набор ещё импортируется, у версии уже есть расчёты |
| 503 | очередь расчётов заполнена |
| 507 | на диске нет места для файла |

## Нагрузка

Импорты и расчёты идут в ограниченных пулах (по умолчанию по 2 одновременно), остальные ждут в очереди до 200.
Запросы чтения (статус, списки, тайлы, слои, выгрузка) обслуживаются сразу. Прогон 50 одновременных пользователей —
[metrics.md](metrics.md#пользовательская-нагрузка-замер-16092026).
