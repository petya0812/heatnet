# Точки подключения без маршрута

Сервис обрабатывает все точки подключения набора за один запуск (R-NET-1). Если точка не подключена, она не
пропадает: её id попадает в `unconnected_oks_ids` сводки варианта, за неё начисляется штраф, а причина видна в API
и на карте (R-UNC-1). Отсутствие маршрута не значит, что подключение технически невозможно: это результат автоматического
поиска по правилам кейса.

## Когда точка остаётся без маршрута

Только если допустимой трассы нет. Отказаться от технически возможного подключения ради лучшей оценки S нельзя,
даже если трасса дороже штрафа (ТП 2.5, разъяснение 15; R-UNC-2).

| Причина (`reason`) | Что значит | Что сделать с данными |
|---|---|---|
| `NO_CONNECTION_POINT` | у объекта ОКС нет точки подключения (старые наборы с `oks_future`) | добавить `oks_connection_point` |
| `FLOW_EXCEEDS_MAX_DN` | расход больше пропускной способности наибольшего ДУ таблицы 1 (ДУ 1400) | проверить `flow_tph`, разделить нагрузку |
| `NO_NETWORK` | нет существующей сети, связанной с источником (вся сеть оторвана или пуста) | проверить геометрию сети и положение источника |
| `NO_ROUTE` | в радиусе поиска (до 5 км) нет трассы, удовлетворяющей отступам и правилам пересечений: точка окружена запретными зонами, проход уже других отступов, пересечение возможно только под острым углом | в `detail` — радиус поиска, ДУ и расстояние до сети; при строгих углах поворота (`turn_angles_strict`) — ещё «повороты только под …»: такой ОКС подключается, если разрешить любые углы |
| `LENGTH_LIMIT` | ни один допустимый ДУ не укладывается в предельную длину пути (R-NET-11) | в `detail` — длина трассы, ДУ и предел; нужно место присоединения ближе или совместное подключение |
| `SEARCH_LIMIT` | поиск остановлен по лимиту перебора (20 000 раскрытий) — защита от зависания на аномальных данных | сообщение `route.search_limit` в диагностике |

Все случаи дополнительно пишутся в диагностику расчёта (`route.not_found`, `oks.no_connection_point`,
`oks.flow_exceeds_max_dn`, `route.search_limit`).

## Как это выглядит в результате

- **Выгрузка (ТП 7)** — id точки в `unconnected_oks_ids` сводки варианта (тип идентификатора сохраняется);
  штраф — в `unconnected_penalty` (100 млн руб. + 0,5 млн руб. × расход, т/ч) и входит в `calculated_cost` и S.
  Отдельных объектов для неподключённых точек в выгрузке нет — формат ТП 7 их не предусматривает.
- **API** — `GET /api/runs/{id}`, в каждом варианте `summary[].unconnected[]`:
  ```json
  {"oks_id": "oks-big", "flow_tph": 30000.0, "reason": "FLOW_EXCEEDS_MAX_DN",
   "reason_text": "расход больше пропускной способности наибольшего ДУ", "detail": "30000.0 т/ч"}
  ```
- **Карта** — слой «ОКС без маршрута»: точка подключения (или контур её полигона) красным, в карточке — причина,
  подробности и что попробовать; в панели результата — список, по клику карта переходит к объекту.

## Влияние на варианты

Разные варианты могут отличаться составом неподключённых точек: это одно из условий различимости вариантов
(ТЗ 2.8). Если в одном варианте точка подключена, а в другом нет, разница в S включает её штраф — ранжирование это
учитывает.
