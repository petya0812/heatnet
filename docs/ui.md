# Интерфейс: шаги, экраны, карта, показ построения

Статика лежит в jar (`src/main/resources/static`), отдельной сборки фронта нет: ES-модули без сборщика, карта —
MapLibre GL из webjar, знаки — свой спрайт `icons.svg` (контурные 24×24 в духе Lucide). Интернет не нужен.
Этот документ описывает то, что есть в коде; предложения на будущее — в конце.

## Четыре шага

Работа идёт по шагам, они же — адреса страницы. Степпер в шапке показывает, где пользователь, что сделано
(галочка), что идёт (вращение), что требует внимания (восклицательный знак) и что пока недоступно (и почему —
подсказка).

| Шаг | Адрес | Что на экране |
|---|---|---|
| Исходные данные | `#/` | загрузка файла; наборы по группам: «Проекты» (первыми), «Загруженные наборы», «Примеры» и «Большие наборы» (свёрнуты) |
| Проверка данных | `#/datasets/{ds}` | готовность к расчёту, ошибки и замечания, как прочитаны данные (что восполнено), состав набора, правки входных данных (ограничение рисуется на карте, сохраняется новой версией) |
| Расчёт | `#/datasets/{ds}/calculate` | кнопка «Рассчитать», название и заметка, параметры по группам, история расчётов |
| Результат | `#/datasets/{ds}/runs/{run}/variants/{v}` | вкладки «Вариант · Сравнение · Выгрузка»: варианты с оценкой S, показатели, структура стоимости, проверка правил, нагрузка на существующую сеть, предельная длина, список ОКС; карточка ОКС — `…/oks/{id}` |
| — Сравнение | `#/datasets/{ds}/compare/{runA}:{vA}/{runB}:{vB}` | два варианта рядом: различия входа, показатели с разницей, общая и различающаяся геометрия |
| — Выгрузка | `…/variants/{v}/export` | файлы: результат в формате обмена (основной), вариант, отчёт HTML, журнал построения |

Сравнение и выгрузка — не шаги, а действия над результатом, поэтому живут вкладками внутри «Результата».

Под шапкой — строка контекста: Наборы › набор (версия) › расчёт › вариант › ОКС. Каждая часть — ссылка.
Заголовок каждого шага повторяет его название со знаком, справа — статус объекта (набора, расчёта).

## Группы наборов

Имя набора в сервисе — имя загруженного файла. Скрипт `tools/seed_datasets.py` называет наборы
`«Группа · Название»`; интерфейс делит имя по « · » и раскладывает по группам: префикс «Проект» — группа «Проекты» (первой),
«Пример» — «Примеры», «Нагрузка» — «Большие наборы». Загруженные вручную файлы — в группе «Загруженные наборы».
По умолчанию скрипт заводит четыре набора: «ЗИЛ» (конкурсный набор, группа «Проекты»), «ЗИЛ с окружением OSM»,
«Все правила на 6 ОКС», «Ошибки во входных данных»; `--all` — все.

## Параметры расчёта

Каталог параметров (`GET /api/params`, `ParamCatalog`) делит всё, от чего зависит расчёт, по происхождению;
экран «Расчёт» показывает четыре группы в этом порядке:

| Группа | Класс каталога | Что внутри |
|---|---|---|
| Настройки трассировки | `algorithm`, изменяемые | дополнительный отступ от зданий и ограничений (м), минимальный угол пересечения дорог и трамвайных путей (45–90°), углы поворота трассы (любые до 90° / 30°, 60°, 90° / 45° и 90° / только 90°) и что делать, если трассы с ними нет, совместное подключение, штраф за поворот |
| Недостающие данные | `data_assumption` | расход существующей сети (свободна / частично загружена), доля загрузки; остальные — только для чтения |
| Правила проектирования | `norm` | таблица «правило · значение · пункт документа» с замком, переключателей нет |
| Как применяются правила | `interpretation` | решения там, где правило можно прочитать по-разному |

Под названием параметра — пункт документа, из которого он взят (технические требования, СП 124); у решений сервиса
пункта нет. Разъяснения, на которых основано правило, — только в [parameters.md](parameters.md). Строка «Если
трассы с такими углами нет» показывается, только когда углы поворота ограничены (`depends_on` с `not`).

Настройки только ужесточают правила: планировщик прибавляет отступ, повышает требуемый угол и сужает набор углов
поворота, а `OutputValidator` проверяет минимумы технического приложения, так что результат с любыми настройками проходит проверку
(`EngineerPreferencesTest`). Числа — слайдер плюс поле с единицей; выбор — сегмент-контрол; изменённый параметр
подсвечен и сбрасывается кнопкой. Значения черновика хранятся в браузере до запуска.

## Результат

- Вкладки вариантов: номер, оценка S, место, стоимость, способ (совместное / раздельное); лучший — с кубком.
- Шесть плиток: «Оценка S», «Стоимость, млн ₽», «Новая сеть», «Врезок», «Новых камер», «Не хватит ДУ» (участков
  существующей сети, которым не хватит пропускной способности; в стоимость не входит).
- Структура стоимости полосой и подписями; проверка правил — бейджем (число правил, нарушения по раскрытию).
- Карточки «Пропускная способность существующей сети» (таблица участков: расход до → после, ДУ есть → нужен) и
  «Предельная длина» (части одного ДУ, длина, предел, доля).
- Список ОКС: расход, присоединение (своя врезка или разветвление от врезки), ДУ, длина и стоимость своей ветки;
  фильтр «Не подключены». Карточка ОКС: путь от источника, новые участки с долей предельной длины, выбор места
  врезки из журнала построения; кнопки «На карте», «Поиск трассы», «В построении».

Главное действие результата — «Выгрузить»; «Построение» и «Сравнить» рядом.

## Карта и легенда

- Слои входа — векторные тайлы района; слои результата — GeoJSON варианта; накладки (показ построения, поиск,
  сравнение) добавляются своим префиксом через `map/map.js`.
- Легенда — панель слоёв справа в группах: исходные данные, новая сеть, существующая сеть (расход до / после,
  «нужен больший ДУ»), замечания, слои анализа, подложка. Слой «Предельная длина» включён по умолчанию.
- Клик по карте открывает один объект — самый значимый из попавших под курсор (точки результата, затем линии
  результата, затем вход; здания последними), остальные упомянуты числом. Подписи полей — с заглавной, стоимость
  в млн ₽; из точки подключения и неподключённого ОКС — переход к карточке ОКС.
- Выделение — ореол под объектом; при смене страницы или набора выделение, всплывающие окна и проигрыватель
  закрываются.
- Цвета карты принадлежат данным и собраны в `map/map.js` (`DN_STOPS`, `RESTRICTION_COLORS`); в модулях
  интерфейса цвета только через переменные `app.css` (`tools/check_tokens.py`); слои сравнения берут цвет из
  переменных через `cssVar`.

## Показ построения

Журнал построения (`GET /api/runs/{id}/journal`) проигрывается на карте: ОКС подключаются по одному, видны
рассмотренные места врезки и выбранное. Пока расчёт идёт, журнал догоняется. Пульт: к началу, шаг назад, пуск /
пауза, шаг вперёд, в конец, перемотка, скорость, фильтр по ОКС. Из карточки ОКС показывается только его
подключение; «Поиск трассы» показывает точки поворота, просмотренные точки и отвергнутые отрезки.

## Оформление

Токены цвета, шкала текста (18 / 14 / 13,5 / 12,5 / 11 px) и размеры панелей — в начале `app.css`. Кнопки трёх
уровней: главная (одна на экран), обычная, тихая (без рамки); повторяющиеся действия в строках — кнопки-знаки с
подсказкой. Диалоги вместо `prompt`/`confirm`. Заголовки разделов — существительные («Как прочитаны данные»,
«Структура стоимости»), не вопросы.

Доступность: контраст текста выше порога AA, у элементов виден фокус, шаги и вкладки проходятся с клавиатуры,
при системном «уменьшить движение» переходы выключаются.

## Устройство кода (`src/main/resources/static/js`)

| Модуль | Отвечает за |
|---|---|
| `main.js` | адрес → данные → экран; строка контекста, вкладки результата, чистка карты при смене страницы |
| `core/router.js` | адрес как место работы: четыре шага, вкладки результата |
| `core/api.js`, `core/store.js`, `core/data.js` | клиент API, общее состояние с подписками, загрузка с опросом |
| `core/dom.js`, `core/format.js` | построение элементов с обновлением на месте, числа и слова |
| `ui/components.js` | знаки, бейджи, статусы, карточки, вкладки, диалоги, уведомления |
| `ui/stepper.js`, `ui/glossary.js` | степпер с состояниями; справка (порядок работы, метод, термины, API) и подсказки к терминам |
| `steps/data.js`, `check.js`, `calc.js`, `result.js`, `compare.js`, `export.js` | экраны шагов и вкладок |
| `map/map.js`, `map/legend.js`, `map/draw.js` | карта, слои, выделение, всплывающие окна; панель слоёв; рисование контура правки |
| `anim/player.js`, `anim/settings.js`, `anim/flow.js` | показ построения и поиска, настройки показа, анимация потока |

Проверки: `python3 tools/check_js.py` (синтаксис модулей), `python3 tools/check_tokens.py` (цвета только через
переменные).

## Заложено на будущее

| Расширение | Куда встраивается |
|---|---|
| Панель свойств справа (клик по объекту открывает карточку в панели, а не во всплывающем окне) | третья колонка при ширине ≥ 1440 px |
| Правки входа сверх ограничения: снять объект, изменить атрибут | операции `remove_object`, `set_attribute` уже есть в API версий |
| Ручная проработка маршрута | отдельный слой и отдельная выгрузка; по ТЗ 2.12 не смешивается с автоматическим результатом |
| Режим с глубиной | ещё один результат расчёта со своим разбором и выгрузкой |
