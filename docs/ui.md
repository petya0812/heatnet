# Интерфейс: шаги, панели, карта, показ построения

Исходники интерфейса — в `frontend/` (Vue 3, TypeScript, Tailwind CSS 4, примитивы Reka UI, иконки Lucide, шрифт
Onest, карта — MapLibre GL). Сборка кладёт готовую статику в `src/main/resources/static`, поэтому jar, Maven и Docker
работают как раньше и интернет при запуске не нужен: шрифт, иконки и карта лежат внутри сборки. Прежний интерфейс
сохранён без изменений по адресу `/classic/` (исходники — `frontend/public/classic`).

```bash
npm --prefix frontend ci            # зависимости (один раз)
npm --prefix frontend run dev       # http://localhost:5173, API — запущенный сервис на :8080 (HEATNET_API=… — другой)
npm --prefix frontend run build     # проверка типов и сборка в src/main/resources/static — её и коммитить
```

После правки интерфейса собранную статику коммитить вместе с исходниками: сборка в Docker и на стенде фронт не
собирает.

## Раскладка

Карта занимает весь экран, всё остальное — скруглённые панели поверх неё, одного вида:

| Где | Что |
|---|---|
| Сверху слева | знак сервиса (к списку наборов) и переключатель набора с поиском |
| Сверху по центру | шаги работы с состоянием каждого |
| Сверху справа | идущие расчёты, вид и анимация (тема, показ построения), справка, API |
| Слева | панель текущего шага: шапка — тело с разделами — низ с главным действием |
| Справа | инструменты карты (слои, показать всё, подложка, масштаб); панель слоёв; карточка объекта, по которому щёлкнули |
| Снизу по центру | показ построения или поиска трассы |
| У края панели | язычок «Скрыть панель»: панель уезжает, карта — на весь экран; переход на другой шаг показывает её снова |

Панель шага всегда устроена одинаково, чтобы было видно, где начало и где конец: в шапке — ссылка назад, номер и
название шага, название объекта; в теле — разделы; внизу закреплено главное действие шага («К расчёту»,
«Рассчитать», «Выгрузить») и короткая подпись, что произойдёт или почему действие недоступно. На телефоне панель
становится шторкой снизу, карта остаётся сверху.

## Шаги и адреса

Адрес — место в работе: перезагрузка или ссылка коллеге открывают то же. Адреса прежнего интерфейса работают.

| Шаг | Адрес | Что на экране |
|---|---|---|
| Данные | `#/` | загрузка файла, библиотека наборов с поиском и группами («Проекты» первыми); у набора с расчётами — переход сразу к последнему результату |
| Проверка | `#/datasets/{ds}` | готовность к расчёту, ошибки и замечания (каждое — на карте, с примерами объектов), как прочитаны данные, состав, правки входных данных |
| Расчёт | `#/datasets/{ds}/calculate` | вкладки «Новый расчёт» и «История» (`?tab=history`); `?param=key` — к параметру, `?from={run}` — параметры прежнего расчёта |
| Результат | `#/datasets/{ds}/runs/{run}/variants/{v}` | вкладки «Вариант · Сравнение · Выгрузка»; карточка ОКС — `…/oks/{id}`; `#/datasets/{ds}/result` — последний готовый расчёт |
| — Сравнение | `#/datasets/{ds}/compare/{runA}:{vA}/{runB}:{vB}` | два варианта: показатели с разницей, общая и различающаяся сеть на карте, различия входа |
| — Выгрузка | `…/variants/{v}/export` | файлы: результат (основной), вариант, отчёт HTML, журнал построения |

Шаги в верхней строке показывают состояние: готово (галочка), выполняется (вращение), есть замечания (треугольник),
недоступно — с подсказкой почему. Сравнение и выгрузка — не шаги, а действия над результатом.

## Сценарии

- **Первый расчёт.** Данные → файл → проверка открывается сама → «К расчёту» → «Рассчитать». Пока идёт расчёт, сеть
  растёт на карте; по готовности — уведомление и кнопка «Открыть» в панели. Уйти с экрана можно: слежение за расчётом
  продолжается, уведомление придёт на любом шаге.
- **Вернуться к работе.** Переключатель набора сверху слева или «Результат →» на карточке набора; «История
  расчётов» — из шапки результата.
- **Поменять настройку и пересчитать.** Из результата или истории — «Изменить параметры и пересчитать»: форма
  открывается с параметрами этого расчёта. Изменённые параметры подсвечены и сбрасываются по одному или все сразу;
  черновик живёт, пока открыт набор (уход на другой шаг его не сбрасывает, другой набор или перезагрузка — сбрасывают).
- **Сравнить.** Вкладка «Сравнение»: по умолчанию — второй вариант того же расчёта; любой вариант любого расчёта
  этого набора и его версий выбирается списком, «Поменять местами» — одной кнопкой.
- **Разобраться с ОКС.** Наведение на строку списка подсвечивает трассу на карте, щелчок открывает карточку: путь от
  источника, новые участки, выбор места врезки; «Поиск трассы» и «Построение» по этому ОКС. Не подключённый ОКС —
  причина и что можно сделать.
- **Поправить данные.** Проверка → «Правки входных данных» → «Нарисовать ограничение» → контур на карте → тип и
  комментарий → «Сохранить новой версией». Исходный набор не меняется.

## Расчёт: порядок настроек

Сверху вниз — только то, что можно изменить, по группам каталога (`GET /api/params`, `ParamCatalog`):
«Трассировка» (`algorithm`), «Здания: ввод и проход» (`interpretation`), «Недостающие данные»
(`data_assumption`). Число — слайдер и поле с единицей; выбор из двух коротких вариантов — сегмент-контрол; из трёх
и больше или с длинными названиями — карточки, где у каждого варианта сразу видно, что он делает. Зависимый параметр
показан отступом под своим и появляется, только когда нужен (`depends_on`). Описание и пункт документа — в
подсказке у названия. Ниже — название и заметка (необязательно) и свёрнутый раздел «Неизменяемые правила»:
технические требования и решения сервиса с источником каждого. Кнопка «Рассчитать» — всегда внизу панели, рядом —
сколько настроек изменено.

## Карта

- Слои входа — векторные тайлы набора; слои результата — GeoJSON варианта; накладки (построение, поиск, сравнение,
  рисование) — каждая со своим префиксом через `map/engine.ts`.
- Панель слоёв — группы «Новая сеть», «Существующая сеть» (расход до / после), «Замечания», «Слои анализа»,
  «Исходные данные», подложка. Видимость слоёв запоминается в браузере.
- Щелчок по карте открывает карточку объекта справа (не всплывающее окно): самый значимый из попавших под курсор,
  остальные упомянуты числом; из точки подключения и неподключённого ОКС — переход к карточке ОКС. `Esc` закрывает.
- Выделение — синий ореол под объектом; при смене шага выделение и карточка объекта закрываются, показ построения
  остаётся только между расчётом и его результатом.
- Цвета данных (ДУ, типы ограничений, состояния объектов) — в `map/palette.ts`; от темы зависит только основа
  (фон, здания, существующая сеть).

## Показ построения

Журнал построения (`GET /api/runs/{id}/journal`) проигрывается на карте: ОКС подключаются по одному, видны
рассмотренные места врезки с оценкой и выбранное. Пока расчёт идёт, журнал догоняется. Пульт: к началу, шаг назад,
пуск / пауза, шаг вперёд, в конец, перемотка, скорость, фильтр по ОКС; `Пробел`, `←`, `→`. «Поиск трассы» показывает
точки поворота, просмотренные точки и отвергнутые отрезки.

## Оформление

Токены — в начале `frontend/src/styles.css`, для светлой и тёмной темы (выбор: светлая, тёмная, как в системе);
компоненты берут цвет только из них (`tools/check_tokens.py`). Панели — 22 px скругления, полупрозрачный фон с
размытием карты под ним; карточки внутри — 16 px; поля и кнопки — 10–14 px. Кнопки: главная (одна на экран),
обычная, мягкая, тихая, опасная. Числа — моноширинными цифрами. Диалоги вместо `prompt` / `confirm`, уведомления —
снизу по центру, у уведомления о готовом расчёте — действие «Открыть».

## Доступность

Все элементы управления доступны с клавиатуры и подписаны для экранного диктора (кнопки-знаки — `aria-label` и
подсказка); фокус виден; шаги — `aria-current`, переключатели — радиогруппы, раскрывающиеся разделы —
`aria-expanded`; ход расчёта и показ построения объявляются через `aria-live`. Контраст текста — не ниже AA в обеих
темах (проверка axe-core на всех экранах: ни одного нарушения). При системном «уменьшить движение» анимации
выключены. Ссылка «К содержимому» — первой по `Tab`.

## Устройство кода (`frontend/src`)

| Модуль | Отвечает за |
|---|---|
| `main.ts`, `router.ts`, корневой компонент App.vue | вход, раскладка панелей, адреса |
| `sync.ts` | адрес → данные → карта: что показывать и что закрывать при смене места |
| `stores/app.ts` | загруженные копии с сервера и место в работе, опрос, пока что-то идёт |
| `api/client.ts` | клиент HTTP API, загрузка файла с ходом |
| `lib/` | числа и слова (`format`), термины (`terms`), каталог параметров (`catalog`), состояния шагов (`steps`), слежение за расчётом (`live`), черновик расчёта (`calcDraft`), производные слои варианта (`variant`), тема, уведомления, диалоги |
| `map/` | карта и слои (`engine`), палитра данных, рисование контура (`draw`), показ построения и поиска (`player`), анимация потока, настройки анимации |
| `components/ui/` | кнопки, подсказки, сегмент-контролы, карточки выбора, переключатели, слайдер, разделы, диалог, меню, список выбора, показатели |
| `components/shell/` | верхняя строка, шаги, переключатель набора, каркас панели, вкладки результата, инструменты и слои карты, карточка объекта, пульт показа, справка |
| `views/` | экраны: данные, проверка, расчёт, результат (с карточкой ОКС), сравнение, выгрузка |

Проверки: `python3 tools/check_js.py` (типы и шаблоны, vue-tsc), `python3 tools/check_tokens.py` (цвета только
токенами). Для сквозных проверок в странице есть `window.heatnet.snapshot()` — состояние только для чтения.

## Заложено на будущее

| Расширение | Куда встраивается |
|---|---|
| Правки входа сверх ограничения: снять объект, изменить атрибут | операции `remove_object`, `set_attribute` уже есть в API версий; в интерфейсе — раздел «Правки входных данных» |
| Ручная проработка маршрута | отдельный слой и отдельная выгрузка; по ТЗ 2.12 не смешивается с автоматическим результатом |
| Режим с глубиной | ещё один результат расчёта со своим разбором и выгрузкой — вкладкой результата |
